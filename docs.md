# PayGrid — API Reference

> Spec type: codebase. Generated by Weldrr discovery.

## Overview

PayGrid is a programmable accounts receivable platform. It gives businesses Dedicated Virtual Accounts (DVAs) so inbound bank transfers can be automatically matched to customers and invoices. The public REST API (`/api/v1`) lets a customer-managed API key manage customers, virtual accounts, invoices, transactions, the business profile, and outgoing webhook subscriptions. Every public endpoint requires a `Bearer` API key and grants/denies access by OAuth-style scopes.

Coverage gaps to note:
- `apps/api/src/routes/api-v1/payouts.routes.ts` defines `POST /api/v1/payouts` (a bank transfer), **but it is NOT mounted** in `api-v1.routes.ts`, so the route is not actually served. Treat it as unreachable/aspirational; it is excluded from the SDK surface below.
- All list endpoints use cursor pagination (`id`-based, `lt`) returning `meta.cursor`; the first page omits `cursor`.
- Internal Nomba identifiers are stripped from responses (`nombaAccountHolderId` on virtual accounts; `nombaTransactionId`, `nombaRequestId`, `eventType` on transactions), but are included for payouts.
- Scopes used by routes are `customers.read/write`, `invoices.read/write`, `transactions.read/write`, `business.read`, and `webhook.read/write`. An API key with empty scopes bypasses the scope check.

## Endpoints (17)

### `GET /api/v1/customers`
**Summary:** List customers for the authenticated business (searchable, cursor-paginated, sortable).
**Operation ID:** `listCustomers`
**Request body:** none
**Query params:** `cursor`, `pageSize`, `q` (search name/email), `sort` (`"created_at:asc"`)
**Responses:**
| Status | Body |
| --- | --- |
| 200 | `{ success: true, data: CustomerSummary[], meta: { cursor: string \| null } }` |
| 401 | `{ success: false, error: string }` |
| 403 | `{ success: false, error: string }` |
**Auth:** API key bearer, scope `customers.read`

`CustomerSummary`: `{ id, name, email, billingEmail, phone, country, countryCode, createdAt, businessId, invoiceCount }`

## Internal endpoints (excluded)

These are intentionally **not** part of the SDK surface and no methods are generated for them:

- **`/auth/*`** — Google OAuth login + callback (`auth.routes.ts`). Dashboard user auth, redirects; not customer-callable.
- **`/files/*`** — Upload/download of images/KYC documents (`files.routes.ts`). Protected by the dashboard JWT (`auth.middleware`); used by the product UI.
- **`/chat/*`** — AI assistant chat (`chat.routes.ts`). Protected by dashboard JWT, for the product UI only.
- **`/trpc/*`** — the entire dashboard business-logic API (tRPC router). Authenticated with the dashboard user JWT/session for the React dashboard, not API keys. Customer-callable behavior lives in the REST `/api/v1` routes instead.
- **`/webhooks/nomba`** — inbound Nomba payment/payout webhook receiver the platform is called **into** (HMAC-signed by Nomba, not customer-callable). No SDK method generated.
- **`/health`** — operational liveness check.
- **`/docs`** — static documentation site (SPA fallback).
- **`POST /api/v1/payouts`** (defined in `payouts.routes.ts`) — **not mounted** in `api-v1.routes.ts`, so not reachable. Excluded and flagged as a coverage gap.
