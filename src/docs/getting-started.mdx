# Getting started

This guide walks through calling the PayGrid API end to end. It takes about
five minutes.

## Base URL

All public endpoints live under `/api/v1`:

```
https://{your-api-host}/api/v1
```

## API keys

Every request must include a `Bearer` API key in the `Authorization` header.
Each key is scoped: a key only works on endpoints whose required scope it
carries.

```
Authorization: Bearer pk_live_...
```

See [Authentication](/docs/authentication) for the full scope reference.

## Your first request

List the customers for your business:

```bash
curl "https://{your-api-host}/api/v1/customers?pageSize=50" \
  -H "Authorization: Bearer pk_live_..."
```

```json
{
  "success": true,
  "data": [],
  "meta": {
    "cursor": null
  }
}
```

An empty list is a valid first response — you have not created any customers
yet. `meta.cursor` is omitted on the first page.

## Create a customer

```bash
curl -X POST "https://{your-api-host}/api/v1/customers" \
  -H "Authorization: Bearer pk_live_..." \
  -H "Content-Type: application/json" \
  -d '{
    "name": "Ada Lovelace",
    "email": "ada@example.com",
    "country": "Nigeria",
    "countryCode": "NG"
  }'
```

Creating a customer upserts by email: if a customer with the same email already
exists, it is updated instead.

```json
{
  "success": true,
  "data": {
    "id": "cus_123",
    "businessId": "biz_456",
    "name": "Ada Lovelace",
    "email": "ada@example.com",
    "phone": null,
    "billingEmail": null,
    "country": "Nigeria",
    "countryCode": "NG",
    "createdAt": "2026-01-01T00:00:00Z",
    "updatedAt": "2026-01-01T00:00:00Z"
  }
}
```

## Provision a virtual account

Give the customer a dedicated account number so they can pay by bank transfer:

```bash
curl -X POST "https://{your-api-host}/api/v1/virtual-accounts" \
  -H "Authorization: Bearer pk_live_..." \
  -H "Content-Type: application/json" \
  -d '{
    "accountRef": "ada-main",
    "accountName": "Ada Lovelace",
    "accountNumber": "0123456789",
    "customerId": "cus_123",
    "currency": "NGN"
  }'
```

## Create and send an invoice

Create an invoice for the customer. The response includes a generated
`paymentUrl` you can share:

```bash
curl -X POST "https://{your-api-host}/api/v1/invoices" \
  -H "Authorization: Bearer pk_live_..." \
  -H "Content-Type: application/json" \
  -d '{
    "invoiceNumber": "INV-0001",
    "amount": 25000,
    "customerId": "cus_123",
    "currency": "NGN"
  }'
```

New invoices default to `draft`. Send one to transition it to `unpaid`:

```bash
curl -X POST "https://{your-api-host}/api/v1/invoices/inv_789/send" \
  -H "Authorization: Bearer pk_live_..."
```

## Errors

Failures return non-2xx status codes with a JSON body:

```json
{
  "success": false,
  "error": "name is required"
}
```

| Status | Meaning |
| --- | --- |
| 400 | Invalid request body or invalid state transition. |
| 401 | Missing or invalid API key. |
| 403 | The API key lacks the required scope. |
| 404 | The resource does not exist. |
| 500 | Internal server error. |

## Pagination

List endpoints use cursor pagination with an `id`-based `lt` cursor. The first
page omits `cursor`; subsequent pages pass the previous page's `meta.cursor`:

```
GET /api/v1/customers?pageSize=50
GET /api/v1/customers?pageSize=50&cursor=MTIzNDU2
```
